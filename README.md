# Phi

[中文 README](README.zh-CN.md)

[Phi](https://en.wikipedia.org/wiki/Phi) (/faɪ/, /fiː/) takes its name from the Greek letter φ. In mathematics, it often represents the golden ratio.

Phi is a minimal coding CLI, written in Rust and built on [Rig](https://github.com/0xPlaygrounds/rig). Its reusable agent harness exposes a public Agent API for execution, delegation, and orchestration. Work locally in the terminal, or keep Agents running behind a Gateway and access them from the CLI, Web, Telegram, or Feishu.

Phi draws on many ideas from [Claude Code](https://github.com/anthropics/claude-code) and [pi](https://github.com/badlogic/pi-mono). Special thanks!

Phi started with a simple idea: everyone should have an agent framework and starter kit of their own. Rather than trying to match the breadth of Claude Code/Pi, Phi provides a foundation you can freely extend and tailor to your own needs.

About 70% of Phi’s code was generated by AI. It’s an experiment in learning about and building agents, and it still has some problems and bugs. After more than six months of daily use and continuous iteration, it just works! (Linux only.)

## Core capabilities

- **Batteries-included tools.** Built-in Bash, Read, Write, Edit, Grep, and Glob tools cover command execution, file editing, and search. Track foreground and background executions, with permission rules and human-in-the-loop approval for tool calls, plus sandbox rules for filesystem access.
- **Built-in Agents and a reusable harness.** Delegate tasks to subagents with separate histories, or use Teams for asynchronous messaging and shared task lists. The agent harness exposes a public Agent API for execution, delegation, and orchestration in your own applications.
- **Memory and navigation.** Rewind to earlier points and navigate the conversation tree to explore different branches. Opt-in Memory preserves knowledge across sessions, while Tape anchors mark work checkpoints for search and context recovery.
- **Change how you work.** Switch providers, models, reasoning levels, and prompts through named presets. Built-in `default` and `plan` modes support implementation and planning; Plan blocks direct Write/Edit tools, not all possible writes.
- **Extend the workflow.** Load project instructions, skills, prompt templates, and custom Agent definitions. Add MCP tools, Lua extensions, and lifecycle hooks; optionally orchestrate tool calls with JavaScript through Codemode.
- **Choose the interface.** Use the [interactive CLI or one-shot print mode](phi-interactive/README.md), control a foreground subprocess with [`phi --rpc`](phi-interactive/README.md#machine-control), or use the [Gateway](phi-remote/README.md) for hosted Sessions that keep running when clients disconnect. Remote plugins are opt-in.

## Workspace

Phi separates reusable execution and UI libraries from application workflows and remote transport.

| Crate | Responsibility |
|---|---|
| [`phi-sdk`](phi-sdk/) | Agent execution, delegation, transcripts, tools, and lifecycle hooks. |
| [`phi-tui`](phi-tui/) | Reusable terminal UI runtime and components. |
| [`phi-interactive`](phi-interactive/) | The `phi` CLI, runtime preparation, Session persistence, and stdio RPC. |
| [`phi-remote`](phi-remote/) | Gateway, device authorization, and Web, Telegram, and Feishu plugins. |
| [`phi-codemode`](phi-codemode/) | Isolated JavaScript execution and host-tool bridging through QuickJS and Wasmtime. |

## Get started

Building Phi requires Rust 1.97 or newer (required by Wasmtime 50).

Optional: the Web interface requires [building Web assets separately](phi-remote/README.md#build-web-assets), using Node.js 22 or newer and pnpm. Cargo does not build them automatically. Neither the CLI nor Gateway requires Node.js to build or run.

From the repository root, install Phi into Cargo's binary directory (normally `~/.cargo/bin`; ensure it is on your `PATH`):

```bash
cargo install --path phi-interactive --locked
```

Install `bubblewrap` (`bwrap`) for the default Linux sandbox, or explicitly set `sandbox.enabled` to `false` if you cannot use it. Configure a provider and model before sending a prompt. Create `~/.phi/settings.json`:

```json
{
  "defaultProvider": "anthropic",
  "defaultModel": "your-model-id"
}
```

Replace `your-model-id` with a model ID supported by your provider and available in Phi's model catalog. For API-key authentication, set the provider's environment variable before launching Phi:

```bash
export ANTHROPIC_API_KEY="your-api-key" # for defaultProvider: anthropic
phi
```

Other providers use `OPENAI_API_KEY`, `GEMINI_API_KEY`, `DEEPSEEK_API_KEY`, `OLLAMA_API_KEY`, or `OPENROUTER_API_KEY`. Prefer environment variables over `--api-key` to avoid exposing credentials in process arguments.

For an OpenAI Codex subscription, run `/login codex` locally. Authorization lasts 30 days and requires a new login when expired; token refresh does not extend it. RPC cannot initiate login.

Phi initializes its model catalog on first run. Set `PHI_OFFLINE=1` to disable online discovery and updates.

## CLI essentials

| Command | Purpose |
|---|---|
| `phi` / `phi "prompt"` | Open an interactive CLI session in the current directory, optionally with an initial prompt. |
| `phi -p "prompt"` | Print one response and exit. |
| `phi -c` / `phi -r` | Continue the latest Session or pick one to resume. |
| `phi --rpc` | Run machine control over stdin/stdout JSONL. |
| `phi list` | List recent saved Sessions in the current working directory. |

Quote multi-word prompts so the shell passes them as one argument, e.g. `phi "Explain this repository"`. A single-word prompt needs no quotes; if it matches a subcommand, use `phi -- "list"` instead. Quotes alone do not distinguish it from the subcommand. Use `phi --help` or `phi <command> --help` for other options, including Session flags. See the [application guide](phi-interactive/README.md) for machine control.

## Settings

Phi loads global `~/.phi/settings.json`, then the current directory's `.phi/settings.json`; project values override global values **per top-level field**, except `agent`, whose `background` and `team` fields merge independently (other nested objects are replaced, not deep-merged). CLI options such as `--provider` and `--model` take precedence where applicable. `PHI_CONFIG_DIR` changes the global config directory. These files use strict JSON.

### Example

```json
{
  "defaultProvider": "anthropic",
  "defaultModel": "your-model-id",
  "defaultThinkingLevel": "medium",
  "sandbox": {
    "enabled": true,
    "whitelist": ["~/.phi"],
    "blacklist": []
  },
  "permission": {"bash": "ask"}
}
```

Reload an active standalone session with `/reload` after editing settings.

### Switches: reusable working presets

A switch groups a provider, model, thinking level, mode, and optional prompt override under one name. Instead of reconfiguring each value separately, choose the preset for the current task and change back when you are done. Add `switches` to `~/.phi/settings.json` (or your project's `.phi/settings.json`):

```json
{
  "switches": [
    {
      "name": "fast",
      "alias": "f",
      "provider": "anthropic",
      "model": "your-fast-model-id",
      "thinking_level": "low",
      "mode": "default"
    },
    {
      "name": "review",
      "alias": "r",
      "mode": "plan",
      "prompt": "Review the proposed changes before editing."
    }
  ]
}
```

Replace the example model ID with one in your catalog. Use `/switch` to select or edit presets, `/switch NAME` or an alias for direct selection, and Ctrl+↑/↓ to cycle in standalone interactive sessions. Picker edits save to global settings; the selected switch stays with the Session.

Omitted fields retain configured or active values. Override the built-in `default` and `plan` presets by name. Plan blocks direct Write/Edit calls even with a custom prompt.

While idle, Ctrl+←/→ adjusts the model's thinking level without changing settings or the active switch.

### Agent delegation

Configure delegation under the top-level `agent` block in `settings.json`:

```json
{
  "agent": {
    "background": true,
    "team": false
  }
}
```

Ordinary subagents can run foreground (the Agent tool waits for the result) or background (returns a launch receipt, then delivers the result later). With no mode specified, master callers default to background and delegated callers to foreground. Teammates are always created asynchronously and collaborate through messages.

`background: true` forces background even when foreground is requested; false or omitted keeps the defaults and explicit choices. `team: true` enables Teams in interactive Sessions without automatically creating teammates. Both settings default to false.

Global/project `agent` fields merge independently. `/reload` applies to that Agent's future delegations, not admitted work or existing children.

### Memory and Tape

Enable Memory with `"memory": {"enabled": true}` and optionally configure `memoryDir.localPath` and `tape`. Automatic context injection requires `"injection": "message-append"`; omitted or `false` disables it. Context goes into the first eligible accepted prompt, not the system prompt.

- `/memory-inject [prompt]` injects context on demand, even when automatic injection is disabled or already consumed. With Tape enabled, the prompt guides selection and is submitted with the context.
- `/memory-inject` without an argument builds context without a prompt query or a fabricated task.

Explicit injection appends a reminder to use `memory_search` and `tape_read` for further lookup. It uses current Memory/Tape data, not a cached payload. RPC submissions use the process Host's Memory settings and Session directory. See the [Memory/Tape design](phi-sdk/src/extension/memory/docs/tape-design.md) for configuration and selection details.

### Hooks

Register lifecycle command hooks in global `~/.phi/settings.json`. Supported events include `SessionStart`, `UserPromptSubmit`, `UserPromptExpansion`, `PreToolUse`, `PostToolUse`, `Stop`, and `Notification`.

```json
{
  "hooks": {
    "enabled": true,
    "PreToolUse": [
      {
        "matcher": "Bash",
        "hooks": [
          {
            "type": "command",
            "command": "bash \"$HOME/.phi/hooks/check-command.sh\"",
            "timeout": 2
          }
        ]
      }
    ]
  }
}
```

Create `~/.phi/hooks/check-command.sh` before using this example. It receives event JSON on stdin; `matcher` selects the exact tool name, and `timeout` is in seconds. Commands run outside the tool sandbox with your process permissions, without Agent approval prompts.

- `hooks.enabled` defaults to `true`. Setting it to `false` disables settings command hooks and Lua hooks, not built-in/Rust hooks or ordinary extension commands and tools. Apply changes with `/reload`.
- Interactive startup asks whether to trust or disable hooks for the workspace. Global `hooks.trust` saves exact absolute paths: `"+/path/to/workspace"` trusts, `"-/path/to/workspace"` disables. RPC and Web startup require a saved decision when process hooks exist.
- Nonempty project hook registrations are rejected. Top-level `hooks` registers lifecycle handlers; `memory.hooks` only configures Memory Git synchronization.

See [command hooks](phi-interactive/README.md#command-hooks) for event fields, script responses, and trust policies.

### Full config example

```jsonc
{
  "defaultProvider": "anthropic",
  "defaultModel": "your-model-id",
  "defaultThinkingLevel": "medium", // Use a level supported by the model.

  // Optional OpenAI-specific controls; omit for other providers.
  "openaiReasoning": {
    "effort": "medium",
    "mode": null, // "pro" only for models that support it.
    "context": "auto",
    "summary": "auto"
  },

  // null leaves these values to the provider and model catalog.
  "max_tokens": null,
  "temperature": null,
  "context_window": null,
  "reserve_tokens": 16384,
  "keep_recent_tokens": 20000,
  "compact_enabled": true,
  "no_tools": false,
  "no_context_files": false,

  "switches": [
    {
      "name": "review",
      "alias": "r",
      "provider": "anthropic",
      "model": "your-model-id",
      "thinking_level": "medium", // Presets use snake_case here.
      "mode": "plan", // Blocks direct Write/Edit, not all possible writes.
      "prompt": "Review changes before proposing edits."
    }
  ],

  "agent": {
    "background": false, // true forces future delegations to background.
    "team": false // Enable Teams for interactive Sessions only.
  },

  // Specific rules override mode; Deny > Ask > Allow.
  // Session grants resolve Ask only. Yolo bypasses all permission rules,
  // but not Sandbox, capability checks, or settings validation.
  "permission": {
    "mode": "ask",
    "nonInteractiveAsk": "deny",
    "read": "allow",
    "grep": "allow",
    "glob": "allow", // Built-in Glob only; shell searches use bash rules.
    "write": "ask",
    "edit": "ask",
    "bash": {
      "*": "ask",
      "git status*": "allow",
      "git push*": "deny"
    },
    // Actual registered tool names; these rules do not load tools.
    "tools": {
      "deploy_preview": "ask",
      "delete_database": "deny"
    },
    // Absolute path patterns for path-aware tools, not a Bash firewall.
    // allow does not grant Sandbox write access; unmatched paths use tool/mode rules.
    "external_directory": {
      "/home/me/shared/**": "allow",
      "/home/me/private/**": "deny"
    }
  },

  "sandbox": {
    "enabled": true,
    "whitelist": [], // Additional writable paths; working directory is writable.
    "blacklist": [] // Hidden paths; takes precedence over whitelist.
  },

  // Global-only, restart required. true relaxes optional RPC file guards,
  // not Sandbox or permissions. Settings/auth stay protected; no RPC login.
  "trust_remote": false,

  "hooks": {
    "enabled": true,
    "trust": [], // Global workspace decisions; see Hooks above.
    "PreToolUse": [] // Global-only command registrations.
  },

  "mcp": true, // Server definitions belong in mcp.json.
  "codemode": {
    "enabled": false,
    "inlineBudget": 3000,
    "cache": true // Default cache directory; false disables, a path relocates it.
  },

  "memory": {
    "enabled": false, // Opt in before using Memory or Tape.
    "memoryDir": {
      "localPath": "~/.phi/memory", // Local Memory repository.
      "repoUrl": null, // Optional Git remote URL for synchronization.
      "globalMemory": "global" // Shared scope directory within the repository.
    },
    "injection": false, // "message-append" enables automatic context injection.
    "skill": true, // Include built-in Memory skill guidance.
    // Memory Git synchronization actions, not general command hooks.
    "hooks": {
      "sessionStart": ["pull"],
      "sessionEnd": [], // Add "push" to sync on Session end.
      "userPromptSubmit": []
    },
    "tape": {
      "enabled": false, // Also requires Memory enabled.
      "onlyGit": true, // Skip Tape outside Git repositories.
      "excludeDirs": [], // Absolute directories in which Tape is disabled.
      "context": {
        "strategy": "smart", // "smart" or "recent-only".
        "fileLimit": 10,
        "memoryScan": [72, 168], // Activity scan window: initial/max hours.
        "alwaysInclude": [], // Memory paths to include regardless of ranking.
        "whitelist": [], // Always include matching files/directories.
        "blacklist": [] // Exclude matching files/directories.
      },
      "anchor": {
        "labelPrefix": "anchor: ", // Display prefix for anchor labels.
        "mode": "auto", // "manual" routes mutations through permission checks.
        "keywords": {
          "global": ["checkpoint"],
          "project": [] // Keywords suggest anchors; they do not force creation.
        }
      }
    }
  },

  // Empty arrays retain auto-discovery. Entries add paths/globs;
  // !pattern excludes; exact +path/-path overrides take precedence.
  // Relative paths use global ~/.phi or project .phi.
  "extensions": [],
  "skills": [],
  "prompts": []
}
```

For `codemode`, `memory`, `memory.tape`, and `sandbox`: `{}` disables, options enable by default, and explicit `enabled` wins. Omitted blocks retain their defaults; CLI overrides and extension exclusions still apply.

In RPC, missing settings files keep their parent directory read-only until created locally and the runtime is prepared again. Neither permissions nor the basic Sandbox fully isolates trusted code or Git hooks.

**Resource tool policy.** Prompt `allowed-tools` pre-approves calls for the current turn; `disallowed-tools` removes whole tools. Agent tool fields select or remove tools without granting permission. Skills provide context only; MCP is configured separately. See [examples and lifetimes](phi-interactive/README.md#prompt-and-agent-tool-settings).

**Resource selection.** Use `phi config` to search and toggle skills, prompts, and Lua extensions. Tab changes global/project scope; `--local` starts in project scope. Space toggles global resources or cycles project inherit/load/unload. Changes save to the corresponding settings file; restart or `/reload` to apply.

Resource arrays accept paths/globs, `!pattern` exclusions, and exact `+path`/`-path` overrides, in that precedence order. Relative paths use `~/.phi` or project `.phi`; project auto-discovered prompts remain under `./prompts`.

## Files under `~/.phi/`

Phi creates files as needed; directories for user-installed resources and optional features may be absent. For example:

```text
~/.phi/                          # Global config directory (override with PHI_CONFIG_DIR)
├── settings.json                # Global settings
├── mcp.json                     # MCP server configuration
├── mcp-cache.json               # Cached public MCP metadata
├── models-store.json            # Discovered model catalog cache
├── auth/                        # Provider login credentials; keep private
├── agents/                      # Custom Agent definitions
├── prompts/                     # Custom prompt templates
├── skills/                      # Installed skills
├── extensions/                  # Lua extensions
├── memory/                      # Optional Memory data; location is configurable
├── projects/                    # Sessions by working directory (override with PHI_SESSION_DIR)
│   └── --path-to-project--/     # Encoded working directory
│       ├── <timestamp>-<id>.jsonl  # Saved Session transcript
│       └── <timestamp>-<id>.lock   # Active Session lock; normally removed on stop
```

OAuth operations temporarily create `auth/<provider>.json.lock` directories and remove them on completion, failure or cancellation.

Session file locks are temporary OS-backed ownership markers. Normal release, errors and cancellation remove the owned lock file; abrupt termination releases the OS lock but may leave a file. The next owner reuses that file automatically, and RPC startup also cleans unheld Session locks in its working-directory scope. Acquisition validates the locked file against its current pathname, so an opener holding an obsolete inode cannot claim ownership after cleanup or replacement.
